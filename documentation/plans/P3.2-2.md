## 2. Routing
**A. No model call (recommended).** Word rules on the user's message and the one before it (so "and are there others?" keeps the last turn's groups), plus the page context.
- Examples: "heading, paragraph, text, block, image" → content; "page, move, delete, rename, publish, draft, version, under" → pages; "attribute, meta, title, description" → attributes; "file, PDF, folder" → files; "user, account" → users; "topic, tag, category" → topics; "person, people, staff, place, review" → external.
- **When nothing matches:** content + pages up to the cap. That covers most requests on a page.
- **For:** costs nothing, adds no wait, gives the same answer every time, and is unit-testable.
- **Against:** misses paraphrases and other languages.

**B. A small model call first (P3.8-2):** gpt-4o-mini classifies the message into groups.
- **For:** handles paraphrase and language.
- **Against:**
  - about 1,500 tokens and 0.5–1 s added to every turn;
  - another provider to configure and fake in tests;
  - not deterministic;
  - its own misses still happen.

**When the router picks wrong:** `get_tool_group(group)` is always offered.
- **What it lists:** its description names the groups and what each is for.
- **What it does:** it adds the group for the rest of the turn, dropping the least-scored group if the cap requires it, and returns the added tools' names and one-line descriptions. One line in the instructions says that only some tools are offered and that `get_tool_group` adds others.
- **The model asks within the turn:** the next inference in the same turn offers the group, so the model asks for it rather than telling the user it can't.
- **Tests and scenario:** a test with a fake provider covers it. Scenario 13 (no such capability) must still say it can't.

**How it works with Neuron 4:**
- Neuron builds its tool registry once per segment. The registry will hold every tool the user's tier allows, so any of them can run.
- A `ChatNode` subclass sends the provider only the offered ones.
- The groups live in the run's `AgentState`, so they survive a pause.
- The toolkit guidelines in the instructions are built per segment from the groups offered at the segment's start. A group added mid-turn brings its guidelines in `get_tool_group`'s result.

**Recommend A, with `get_tool_group`.** P3.8-2 is then dropped, as its entry says.

## 3. Approvals, the loop guard and "Not asked" refusals
- **Approval resume (the decide endpoint):** it continues the same run, so its `AgentState` keeps the groups and the model sees the same tools. A call already approved runs even if its group is no longer offered, because the registry holds every tier tool. Cards, fingerprints and `CallCheck` refusals work by tool name and are unchanged.
- **Loop guard:** its state is in the same run, keyed by tool name. A denied tool stays refused for the turn even if its group is asked for again.
- **A new message while calls wait** (`settleWaitingCalls`): that ends the old run with its own groups. The new message is routed afresh.
- **"Not asked" refusals (`CallCheck`):** independent of what is offered.
- **Tests:** one each for resume, Deny then `get_tool_group`, and a call to a tool not currently offered (runs, still behind its card).

## Risks
- **Routing misses** cost a turn's quality until the model asks. `get_tool_group` and the full ×1 show how often.
- **`ChatNode` is subclassed** (a Neuron internal). A test fails if Neuron changes it.
- **Prompt caching:** OpenAI caches a prefix, so changing the tool list per request lowers cache hits. List price is unaffected, and the runner's estimate ignores caching.
