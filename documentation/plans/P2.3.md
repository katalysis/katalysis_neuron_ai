## 3. No behaviour change: the v3 baseline
**Captured on `development` as it is now** (`b268f3b`, BF-1 and BF-2 merged, Neuron 3.15.26), before any conversion:
1. Back up the dev DB: `documentation/fixtures/backup_dev_db.sh P2.3`.
2. `git switch development` (the dev site then runs v3), run the capture script with `c5:exec` (it builds tools only: no provider call, no write), `git switch` back to the task branch and clear the cache. The script and its output are new, untracked files, so the switch leaves them in place.
3. The script, `tests/Support/capture_tool_baseline.php`, writes `tests/Support/tool-baseline-v3.json`:
   - **per toolkit**, all 12 (registered ones in the agent's order, then `AttributesToolkit`): class name and `guidelines()`, verbatim;
   - **per tool defined** (87): name; description; the provider payload exactly as Neuron's OpenAI `ToolMapper::map()` builds it (the same shape on v3 and v4, so it is what the model receives); and, for a readable diff, each property's name, type, description, required and enum;
   - **what the agent offers** from the core toolkits: `ToolNameResolver::resolve(core, [])` then `DisabledTools::apply()`: the toolkits in order, each one's guidelines as delivered (with `FilteredToolkit`'s "Toolkit: X" line where a tool was removed) and its tool names;
   - the commit and Neuron version it was captured from.
4. The capture is committed with the tests (step 5.2), before the code.

**`ToolBaselineTest`** (integration) builds the same three things on v4 from the converted code and asserts each is **exactly** equal to the JSON (`assertSame` on the decoded arrays, so order counts). The offered list is taken from the real agent's `tools()`, with external toolkits left out. **Any difference is a stop-and-ask**; the expected values are never edited to make it pass.

Outside the baseline, deliberately:
- **The guidelines heading.** v4 heads each toolkit's guidelines with its tool names inside `<TOOLS-GUIDELINES>`; v3 used the class name (P2.1 findings §9). That is Neuron rendering the prompt, not our tool definitions, and it is the same whatever P2.3 does; the prompt belongs to P2.4. I'll record it, not test it. **Confirm (Q1).**
- `katalysis_pro`'s 7 tools: not offered on v4 until P2.8, and its `list_people` and `resolve_file_id_from_path` stop overriding the core ones until then. Already known (findings §5.3).

Behaviour that does change, none of it from the conversion itself (it comes from Neuron 4 or from P2.2's `CallableTool`, both approved):
- **Unknown inputs are refused on every tool**, not only `update_page` (`CallableTool`, P2.2; DELIVERY_PLAN P3.3: "P2.3 moves the check into `CallableTool`"). The message is `StrictInputTool`'s ("… does not accept: X. Nothing was changed. It accepts only: …"). On v3, 86 tools dropped such inputs without a word.
- **A missing or mistyped required input** is answered by v4 with `ToolOutput::error('Parameter "x" is required.')` without running the tool. v3 threw, and our error handler said "Error executing tool: Missing required parameter: x". v4 also casts inputs to the declared types.

Both reach the model only as error text. Neither changes what a tool does when its inputs are valid.

## 4. The conversion method
**Scripted, its own commit, nothing hand-written in it.** A PHP script (text in appendix A, run from the scratchpad, not committed) on the 12 files `src/Tools/*Toolkit.php`, never `src/Toolkits/`:
1. `new Tool(` → `new CallableTool(` (86)
2. `->setCallable(` → `->setHandler(` (87)
3. `use Katalysis\NeuronAi\Tools\Support\CallableTool;` added after `use NeuronAI\Tools\Tool;` (12). The `Tool` import stays, because the `make…Tool(): Tool` return types stay (`CallableTool` is a `Tool`).

The script checks the count for each file against the table it holds before writing and stops if any differs. No closure, property, description or guideline line changes. A reviewer can check the commit by undoing those three substitutions on the diff: the result is empty. The tests get the same kind of scripted commit (`new Tool(` → `new CallableTool(` plus the import) for the two-argument calls in the five test files. Assertions are unchanged.

**Hand-written, in separate commits:**
- `update_page`: `StrictInputTool` becomes a thin subclass of `CallableTool`. `CallableTool` already holds `refuseUnknownInputsWith()` and the check, so the class keeps its name, `defaultMessage()` (delegating to `CallableTool::unknownInputsMessage()`, same text) and nothing else. `update_page`'s code, with its move message, doesn't change. **This deletes about 45 lines of working code** (its `execute()` and fields, now in `CallableTool`): listed here for approval. P3.3 can remove the class.
- `ToolListChecksTest`: the 4 calls with v3's property list become `new CallableTool(...)` plus `addProperty()` calls. Same tools, same assertions.
- `ToolDefinition` and `ToolKind` (5.3).

## 11. Risks and questions
- **Q1. The guidelines heading** (section 3) is left out of the baseline as Neuron's prompt rendering (P2.4). Agree?
- **Q2. Strict inputs on every tool** (section 3) is the one change a model will notice: a call with an extra key that used to "succeed" is now refused. The plan treats it as decided (P2.2's `CallableTool`; DELIVERY_PLAN P3.3). The scenarios will first show it in P2.9. Fine, or do you want it switched off for everything except `update_page` until P2.9?
- **Q3. `ToolDefinition` in the registry.** Recommended: P2.3 brings only the class and its tests. The way another package hands `ToolDefinition`s to `ExternalToolkitRegistry`, without extending Neuron's `AbstractToolkit`, is an extension-API decision that P2.8 needs. It goes in P2.8's core-side PR into `integration/neuron4`. Or do you want it in P2.3?
- **Q4. The 12 Blocks and Versions tools without `guarded()`:** left as they are (no behaviour change). Add them to P3.5's list?
- **Q5. Thin `StrictInputTool`** (about 45 lines removed, section 4) rather than deleting the class. Agree?
- **Risk: the capture depends on the dev DB** only if a toolkit reads it while building its tools. None appears to (the descriptions are literals), but the test runs as integration in case. If the capture shows anything site-dependent, I'll say so.
- **Risk: strict inputs and existing tests.** An existing test that passes an undeclared key to a core tool would now fail with the refusal. That is a stop-and-ask, not an assertion change.
- **Risk: `getResult()` is `string|ToolOutput` on v4.** A test that reads it as a string might fail on a v4 error result. Same rule: stop and ask.

## Appendix A: conversion script (run from the scratchpad, not committed)
Dry run on a copy of `src/Tools/` (2026-10-21, while planning): every count matched, 12 files converted, 185 changed lines (86 + 87 + 12), nothing else.

```php
<?php
// php convert.php <package-dir>: the three P2.3 substitutions in src/Tools/*Toolkit.php, with per-file counts.
$expected = [ // file => [new Tool(, ->setCallable(]
    'AttributeSetsToolkit' => [5, 5], 'AttributesToolkit' => [11, 11], 'BlocksToolkit' => [7, 7],
    'FileAttributesToolkit' => [5, 5], 'FilesToolkit' => [7, 7], 'PageAttributesToolkit' => [7, 7],
    'PagesToolkit' => [17, 18], 'PeopleToolkit' => [5, 5], 'TopicsToolkit' => [8, 8],
    'UserAttributesToolkit' => [5, 5], 'UsersToolkit' => [4, 4], 'VersionsToolkit' => [5, 5],
];
$import = "use NeuronAI\\Tools\\Tool;\n";
$add = $import . "use Katalysis\\NeuronAi\\Tools\\Support\\CallableTool;\n";
$files = [];
foreach ($expected as $name => [$tools, $callables]) {
    $path = $argv[1] . "/src/Tools/{$name}.php";
    $src = file_get_contents($path);
    $found = [substr_count($src, 'new Tool('), substr_count($src, '->setCallable('), substr_count($src, $import)];
    if ($found !== [$tools, $callables, 1] || str_contains($src, 'Support\\CallableTool;')) {
        fwrite(STDERR, "$name: expected [$tools, $callables, 1], found [" . implode(', ', $found) . "]\n");
        exit(1);
    }
    $files[$path] = str_replace(['new Tool(', '->setCallable(', $import], ['new CallableTool(', '->setHandler(', $add], $src);
}
$extra = array_diff(array_map(fn ($f) => basename($f, '.php'), glob($argv[1] . '/src/Tools/*Toolkit.php')), array_keys($expected), ['FilteredToolkit']);
if ($extra !== []) { fwrite(STDERR, 'unexpected toolkits: ' . implode(', ', $extra) . "\n"); exit(1); }
foreach ($files as $path => $src) { file_put_contents($path, $src); } // only once every file has passed
echo count($files), " files converted\n";
```
