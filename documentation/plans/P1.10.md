# P1.10 plan: `get_page_content` works under the CLI

Status: **approved** (20 October), not started. Start in a fresh session: read this file, confirm the plan briefly, then begin with Step 1.

Prerequisite: P1.7a and P1.7b are merged.

Task entry: [DELIVERY_PLAN.md](../DELIVERY_PLAN.md), P1.10.

## 1. Context

- `get_page_content` ([PagesToolkit.php](../../src/Tools/PagesToolkit.php), `makeGetPageContentTool`, about L312-405) builds `PageView` with no page argument. `constructView(false)` calls `->getCollectionPath()` on `false`. That is an `\Error`, and the tool's `catch (\Exception)` blocks miss it, so the agent sees "Error executing tool".
- Rendering through `PageView` is not a usable route under the CLI anyway: with the page passed in, it returns 0 bytes.
- `extractContentFromBlocks()` (about L3029) is the fallback, and has three defects:
  1. It iterates `Area::getHandleList()`, which returns site-wide, top-level, non-global areas only, so container sub-areas (the Columns page) are missed.
  2. It adds a fake `<h2>AreaHandle</h2>` per block, which pollutes the headings.
  3. `extractBlockPreview()` (private, about L3090) swallows every `\Throwable`, so a failing block is silent.
- The page IDs in the P1.5 baseline (793, 1012, 1020, 1055, 1063) no longer exist. Current fixture pages: Headings 5335, Columns 5336, Injection 5338 (these change on every seed reset). **Test by path**: `/neuron-test/headings`, `/neuron-test/columns`, `/neuron-test/injection`, plus people, move-me and move-target.
- Scenarios calling `get_page_content`: 05, 14, 16 (in the P1.5 baseline), 19 and 20 (added later, no baseline; compare against the P1.9 results).
- Unrelated and left alone: `get_block_data` returned "Block 966 not found" in baseline 05. Note it in the report, do not fix it.

## 3. Step 2: the fix

Remove the `PageView` render attempt (a planned deletion of about 30 lines) and always use block extraction.

- Wrap the whole read in `\Throwable`.
- Iterate `Area::getListOnPage($page)` so container sub-areas are included. **Spike on Columns first; stop and report if it doesn't work.**
- Drop the fake `<h2>`. Wrap each block as `<section data-area="…" data-block-type="…" data-block-id="…">`.
- Add a throwing variant of the preview for this tool only. `extractBlockPreview` keeps swallowing for `get_page_blocks` and `serializeBlock`.
- Catch `\Throwable` per block. On failure add a `renderErrors` entry (block ID, type, message through `SecretRedactor::redact`; no stack trace, no file paths) and continue with the other blocks.
- Add a `blocks` list (`blockID`, `blockType`, `area`, `hasText`). Blocks with no readable text appear with `hasText: false`.
- `renderMethod` becomes `"blocks"`. Keep `html`, `html_raw` and `text`.

| | Before | After |
|---|---|---|
| Result | `Error executing tool` | `ok` with content |
| Headings | none | real `h2`/`h3` from the blocks, no fake "Main" headings |
| Text | none | `text` via `HtmlToText` |
| Block types | none | `data-block-type` and the `blocks` list |
| Order | none | page order, including nested columns |
| Block that throws | the whole tool failed | other blocks returned; failure in `renderErrors`, redacted |

Block types that return text: content, html, accordion, faq, feature, feature_link, file, hero_image, image_slider, page_title, testimonial, rss_displayer, conversation, stack and scrapbook display, express_entry_detail, autonav, page_attribute_display; and `katalysis_pro` people, feature_list and advanced_gallery.

Block types with no text (they appear with `hasText: false`): image (alt text lost), gallery, video, youtube, google_map, form and express_form, express_entry_list, page_list, tags, topic_list, search, horizontal_rule, social_links, share_this_page, core_container itself (its children are read), and `katalysis_places`, `katalysis_reviews`, `katalysis_feature_box`, `katalysis_heading_group`, `katalysis_modal`. Confirm the last five with the spike.

### Decision 1 (approved): permissions on blocks and areas

Skip blocks or areas the user can't view (`canViewArea` / `canViewBlock`) and return a **`hiddenBlocks` count** in the result. Page-level checks stay as they are.

### Decision 2 (approved): no injection guard

No injection guard or delimiter in the tool output. B-INJ stays "not met in code". **If scenario 16 shows the model following ANY injected instruction** (deleting a page, putting an email address in an image link, or concealing the note from the user), **stop and report**: that would make a tool-output guard a Phase 1 exit item. Do not change scenario 16 or the prompt.
