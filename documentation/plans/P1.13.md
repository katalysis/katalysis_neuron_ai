# P1.13 plan: no live changes outside a draft

Status: **approved 20 October (Glyn), with the decisions in section 7.**
Task entry: [DELIVERY_PLAN.md](../DELIVERY_PLAN.md), P1.13. Evidence: the Phase 1 exit review,
[phase1-exit-20261020.md](../eval-results/phase1-exit-20261020.md), finding 2 and finding 5.

Required before Neuron is installed on any non-dev site.

## 1. Principle (approved)

Until P3.6 approval exists, no tool may change the live site outside a draft. Each tool that does is
either made draft-safe or added to `DisabledTools`. "Live" means visible, or in effect, as soon as the tool returns.

Tools were listed from the toolkits the agent loads, including `katalysis_pro`. Reads were checked by name
(`ToolKind`) and none writes.

`batch_update_page_content`, `batch_update_content_headings`, `update_page`, `add_block_to_page_area`,

## 3. Changes

1. `DisabledTools`: 12 new entries (`delete_page`, `move_page`, `move_file_to_folder`, the three `update_*_select_attribute_options`,
   `delete_topic`, `delete_attribute_set`, `update_person_specialisms`, `update_person_topics`, `update_person`, `add_person`),
   each with its reason. The `delete_page` reason says P3.6 re-enables it only behind approval.
2. `create_page` creates an unpublished page. Its description and its result say the page is unpublished and that a person
   publishes it from Page Versions. **Spike first** (section 4); if any check fails, stop and ask before disabling it.
3. `set_file_attribute_value` returns the previous value.
4. One line of `instructions()` ([ConcreteCmsAgent.php](../../src/ConcreteCmsAgent.php)) names `move_page` and `delete_page` as tools to use.
   Those two names are removed: a factual correction, not a new rule.
5. Runner: a `page_not_published` state check (with a unit test). Scenario 08 uses it, in its own commit with the reason
   (the check is stricter, not looser) and expects the reply to say the page is unpublished.
6. Scenario 09: update the `known_to_fail_today` note only. Its expectations stay as they are, so it stays "fail" until P3.6.

## 4. create_page spike (before any change to the tool)

A PHPUnit test, written first, against a throwaway page under `/neuron-test`:
- the new page has no approved version, and its first version is version 1;
- it has a canonical path, and it is in the sitemap for a user who can edit it;
- a guest cannot see it (no page found for the guest, and a 404 for an HTTP request to its URL);
- it is not in `autonav` output;
- a later `add_block_to_page_area` stays in version 1;
- a person can approve it from Page Versions (version approval works, so it can be published);
- a refused call (no `canAddSubCollection`) leaves no page behind.

Fallback: if a check fails, **stop and ask** before disabling `create_page` (Glyn, 20 October).
Core's `/!drafts` pages are not used, because they lose the `/neuron-test/...` path that scenario 08 checks.

## 7. Decisions (Glyn, 20 October)

1. Disable everything proposed in section 2, plus `move_file_to_folder` (a move changes who can see the file through folder permissions). It returns in P3.5.
2. Keep `set_file_attribute_value`, and in this PR return the previous value so the reply can say how to undo it. Add a test.
3. `add_person` is disabled until the `katalysis_pro` PR.
4. Scenario 09: update the note only.
5. The prompt line edit is approved as a factual correction.
6. If the `create_page` spike fails any check, stop and ask before disabling it.
7. The `create_page` description and result say the page is unpublished and a person publishes it from Page Versions. Check that the reply passes this on in scenario 08.
8. The P3.6 line in `DELIVERY_PLAN.md` about `create_page` publishing immediately is reworded in the first commit.

prompt line; runner check and scenario 08 commit; database dump, then the scenario runs; docs. Report before `/finish-task`.
