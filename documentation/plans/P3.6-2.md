# P3.6-2 plan: approval on every write tool, with previews

Branch `task/P3.6-2-approval-every-write`, base `development`. This task stops for a plan because it changes the approval mechanism. There is no schema change.

## 1. Every offered write is gated
`ApprovalService::gate()` gates every tool that `ToolKind::isWrite()` calls a write, instead of a fixed list of three. External write tools are gated too and get a generic card (B-ACC-8). Each card is built by `ChangePreview` from reads only. The fingerprint is checked again at Approve, for every call in the batch, before any write runs (as in P3.6-1).

- **Batch tools (B-CON-3, B-CON-4):** the card always gives the count and lists every block (area and type) or page (title and path).
  - Above the limit, a warning line comes first: "This changes {n} blocks, more than {limit}."
  - The limit is one named setting: Concrete config `katalysis.ai.approval.block_limit`, default 10, read by `ApprovalSettings` (spec §10 open question 1).
  - When one response holds gated calls on more than one page, the panel heads the cards with "{n} pages: …" (title and path).
- **One matcher for preview and write:** the batch previews use the same matching code as the write (a read-only `plan()` in `BatchEditToolkit`, which `apply()` then runs). The list shown is exactly what would be written.

## 2. Draft ownership (P1.8a)
A draft belongs to the page.
- **The warning:** when the newest version is an unpublished draft whose author isn't the current user, the card's first line says: "This page already has unpublished changes by {name} (version {v}, {date}). Your change is added to that version."
- **What that draft already changes:** a line follows, from comparing the draft with the live version: name, description and template; blocks added, changed or removed in each area.
- **The fingerprint** includes the draft's author and version, so the card can't go stale silently.

## 3. A kept, partly written draft in the Changed line
- When a call fails after writing, `DraftCleanup` keeps the draft (BF-3).
- The `{ok: false}` envelope gains `keptDrafts: [{pageID, versionID}]`, built from DraftCleanup's records, not from the message text.
- `TurnChanges` lists it: "Kept, partly written: {page} ({path}), unpublished version {v}."

## 4. B-WRT-4: workflows
- **No offered tool reaches a Concrete workflow today:** drafts aren't approved and `create_page` adds a page directly. The two that would, `delete_page` (`DeletePageCommand`) and `move_page`, are disabled until P3.6-3.
- **Recommended:** add a shared `WorkflowOutcome` helper now. It reads Concrete's workflow progress after the command. If the change is pending, the result says `status: "submitted_for_approval"`, and `TurnChanges` writes "submitted for approval" instead of "changed".
- **Where it goes:** into `delete_page` and `move_page`, tested by calling the tools directly on a throwaway page that has a basic workflow on its delete and move keys.
- If that fixture can't be built cleanly, I'll stop and ask before moving the wiring into P3.6-3.

## 6. Scenario 09's wrong-page write: the cause is page resolution
- **The cause:** `list_pages` with `includeDescendants=true` passes `"/neuron-test/%"` to Concrete's `filterByPath()`, which adds `"/%"` itself. The query becomes `/neuron-test/%/%`, so it returns only grandchildren.
  - In the Phase 1 exit run 2, the model asked for the descendants of `/neuron-test` and saw only Move Me Child.
  - It concluded that Move Target didn't exist and created it. Concrete gave the new page the path `/move-target-1`.
  - It then moved the child, the only page it had seen. This reproduces today (`list_pages` returns 1 page of 9).
- **The fixes, in tools, red first:**
  1. `list_pages` passes the parent path as Concrete expects (home: all pages).
  2. `create_page` refuses a name whose handle already exists under the parent ("A page {name} already exists at {path}; nothing was created"), instead of Concrete's silent `-1`.

## Risks
- **Fingerprints that are too strict** reject good approvals (for example, a cache table written by a page view). The block fingerprint reads fields through `BlockFields`, not raw rows, and each tool has a test that a plain re-read gives the same fingerprint.
- **The batch split into `plan()` and `apply()`** touches working write code. `HeadingsAndBatchTest`, `BlockTextIntegrityTest` and `FailedWriteCleanupTest` cover it unchanged.
- **More pauses:** every write turn now waits for a click. A turn that writes several things shows several cards, which are decided one by one and then sent together.
- **The workflow fixture** may be awkward to build and clean up (see §4).
- **Cost:** 114 runs. If the first ×1 pass shows a run costing over $0.12, I stop and report before the rest.
